1. INTRODUCTION

1.2 Abstract
StudyBot is an AI-powered study assistant designed to enhance the learning process through an interactive "Study Chat" interface. It utilizes Retrieval-Augmented Generation (RAG), allowing users to upload personal study materials and interact with them using advanced Large Language Models (LLMs). Beyond simple document Q&A, the system features automated OCR for scanned PDFs, integrated web research capabilities, and the generation of Anki-compatible flashcards for active recall. The project is deployed on a Raspberry Pi, demonstrating that complex AI orchestration can be managed on low-power edge devices by offloading heavy inference to specialized cloud APIs.

1.3 Existing System and Need for System

Current study methods often rely on static reading of PDFs or manual note-taking, which lacks interactivity and real-time clarification. While general-purpose AI tools exist, they often lack the "grounding" provided by a user's specific textbooks or local notes. StudyBot fills this gap by ensuring all AI responses are grounded in the user's uploaded documents while offering specialized modes like "Explain," "Quiz," and "Summarize".

1.4 Scope of System

Document Management: Automated text extraction from digital and scanned PDFs using PyMuPDF and Tesseract OCR.
Contextual Chat: Intelligent retrieval and generation using LangChain to answer questions based on specific study materials.
Web-Augmented Research: Ability to search the web using crawl4ai and DuckDuckGo when local documents lack sufficient information.
Active Recall Tools: Automatic creation of flashcards with interactive flip animations and JSON export functionality.
Edge Deployment: A fully functional local server environment hosted on a Raspberry Pi.

1.5 Brief Description of Technology Used

Backend: FastAPI (Python) for building high-performance APIs.
LLM & Embeddings: Groq (Llama 3.3 70B) for fast text generation and Voyage AI for high-quality semantic embeddings.
Vector Database: MongoDB Atlas using $vectorSearch for retrieving relevant document chunks.
Frontend: Vanilla HTML, CSS (Dark Glassmorphism), and JavaScript.


1.6 Operating Systems Used

Development Environment: Windows (used on the personal laptop for writing the code, preliminary testing, and configuring the RAG bot before deployment).
Production/Deployment Environment: Raspberry Pi OS (Debian-based) running on the Raspberry Pi.


2. PROPOSED SYSTEM.

2.1 Study of Similar Systems

Modern educational tools often fall into two categories: general-purpose AI chat interfaces (like ChatGPT) or dedicated study aids (like Anki or Quizlet). While these systems are powerful, they present specific limitations that the proposed system, StudyBot, aims to overcome:
Contextual Limitation: General AI models often lack direct, grounded access to a user's specific, local textbooks without manual copy-pasting.
Manual Effort: Tools like Anki require students to manually create flashcards, which is a time-consuming process.
Feature Fragmentation: Students often have to switch between different platforms for document reading, web research, and testing themselves.
StudyBot bridges these gaps by combining Retrieval-Augmented Generation (RAG) with automated active recall tools in a single interface.



2.2 Feasibility Study

The feasibility of deploying StudyBot on a Raspberry Pi was evaluated across three main dimensions:
Technical Feasibility: By utilizing Groq for LLM inference and Voyage AI for embeddings, the system offloads the heaviest computational tasks to the cloud. This ensures that the Raspberry Pi’s CPU and RAM are not bottlenecks for high-speed AI tasks.
Economic Feasibility: The project uses a low-cost Raspberry Pi and leverages efficient APIs like the llama-3.3-70b-versatile model, which provides fast inference without the need for expensive local GPU hardware.
Operational Feasibility: The use of a Single Page Application (SPA) with a dark glassmorphism design ensures that the interface is modern, lightweight, and easy for students to navigate.


2.3 Objectives of Proposed System
The primary objective of StudyBot is to provide an all-in-one AI study assistant that maximizes learning efficiency. Specific goals include:
Interactive Learning: Allowing users to interact directly with their study materials through a conversational RAG interface.
Automated Processing: Extracting text from digital and scanned PDFs automatically using PyMuPDF and Tesseract OCR.
Specialized Study Modes: Offering three distinct modes—Explain for clarity, Quiz for self-assessment, and Summarize for brevity.
Active Recall: Automatically generating Anki-compatible flashcards to help students memorize material effectively.
Comprehensive Research: Integrating web search via DuckDuckGo to provide context that may be missing from local documents.


2.4 Users of System
StudyBot is designed for a variety of users within the educational and professional sectors:
Students: Individuals looking to master complex textbooks and automate the creation of study materials.
Researchers: Those who need to quickly extract and summarize information from large volumes of PDF documentation.
Self-Learners: Users who require an interactive tool to explain difficult concepts and verify their knowledge through quizzes.

3.3 System Hardware Details

While StudyBot is a software-heavy application, the hardware choice is critical for its "IoT" classification:
Edge Computing: The Raspberry Pi serves as a local host, ensuring the application is accessible within a local network (e.g., http://<raspberry-pi-ip>:8000).
Local Processing: Tasks such as PDF text extraction and OCR (Optical Character Recognition) via pytesseract are performed locally on the Pi's CPU.
API Offloading: To prevent the Pi from overheating or slowing down during heavy AI tasks, LLM inference (Groq) and vector embedding (Voyage AI) are offloaded to external servers

3.6 Design Sequence






The development of StudyBot followed a systematic sequence:

3.7 System Software Details

The backend is structured into modular services to ensure maintainability:
main.py: The entry point that defines the FastAPI application and API routes.
embedding.py: Handles the pipeline of PDF processing, text chunking, and embedding creation.
retriever.py: Contains the logic for searching MongoDB Atlas using vector embeddings.
rag.py: The core orchestrator that chains the retriever and LLM together.
flashcards.py: A specialized service that uses the LLM to generate study aids from document context.

3.8 Process / System Flowchart




Process Path:
User uploads a PDF.
System extracts text; if the PDF is scanned, Tesseract OCR is triggered locally.
Text is "chunked" into smaller segments.
Voyage AI generates embeddings for each chunk.
Chunks and vectors are stored in MongoDB Atlas.
User asks a question; system performs a Vector Search to find relevant chunks.
Groq LLM generates a natural language response based on the found context

4.CODING

4.1 Algorithm

The core functionality of StudyBot is driven by the Retrieval-Augmented Generation (RAG) algorithm, which follows a structured sequence to process documents and generate intelligent responses.
The RAG Pipeline Logic:
Document Ingestion: The system uses PyMuPDF to extract raw text from uploaded PDF files.
OCR Processing: If a document contains scanned images or non-selectable text, Tesseract OCR is triggered locally on the Raspberry Pi to perform character recognition.
Text Chunking: Extracted text is broken down into smaller, manageable "chunks" to ensure high-quality retrieval and stay within LLM context limits.
Vector Embedding: Each text chunk is sent to Voyage AI (specifically the voyage-3 model) to be converted into a high-dimensional numerical vector.
Storage: These vectors, along with their corresponding text segments, are stored in a MongoDB Atlas collection.
Semantic Retrieval: When a user submits a query, the system generates an embedding for that query and performs a vector search in MongoDB to find the most relevant document chunks.
Response Generation: The retrieved context and the original user query are sent to the Groq LLM (Llama 3.3 70B), which generates a grounded, natural language response.\

def get_current_user(authorization: Optional[str] = Header(None)) -> dict:
    """Extract user info from JWT token in Authorization header."""
    if not authorization or not authorization.startswith("Bearer "):
        raise HTTPException(status_code=401, detail="Not authenticated")

    token = authorization.split(" ", 1)[1]
    auth = get_auth()
    user = auth.get_user_from_token(token)
    if not user:
        raise HTTPException(status_code=401, detail="Invalid or expired token")
    return user

6. LIMITATION OF PROPOSED SYSTEM

Hardware Bottlenecks: While LLM tasks are offloaded, the local OCR processing (using Tesseract) runs directly on the Raspberry Pi's CPU. Processing large or highly graphical PDFs can cause significant CPU spikes and temporary system slowdowns.
Internet Dependency: The system's intelligence relies on Groq and Voyage AI APIs. Without a stable internet connection, the RAG chain and embedding generation will fail.
API Quotas: Since the system uses external providers (Groq, Voyage, MongoDB Atlas), it is subject to the rate limits and usage quotas of those specific services.
Retrieval Window: The effectiveness of the "Study Chat" depends on the quality of the initial text chunking and the limited context window of the LLM.

7. PROPOSED ENHANCEMENTS

Local LLM Integration: Future versions could explore using Ollama or LocalAI to run smaller models (like Llama 3 8B) entirely on the Raspberry Pi 5 (8GB) to remove internet dependency.
Expanded File Support: Enhancing the ingestion engine to support .docx, .txt, and .pptx files in addition to standard PDFs.
Multi-User Authentication: Implementing a robust user management system beyond the basic login.html shell to allow multiple students to maintain separate knowledge bases.
Mobile Companion App: Developing a dedicated mobile interface or wrapper to make the StudyBot accessible for on-the-go learning.
Advanced Vector Indexing: Fine-tuning the MongoDB Atlas $vectorSearch parameters or implementing "Hybrid Search" (combining keyword and semantic search) for even higher retrieval accuracy.
